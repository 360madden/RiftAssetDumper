## Part 1: M8.2 — Role-Semantic Mapping (Gate 2 Advanced)

**Type**: Data analysis (population inventory cross-reference)
**Gate**: `descriptor-semantic-map` → advanced from "blocked (improved)" to **"improved — usage-level evidence"**

### What was done
Cross-referenced all 5 descriptor patterns with Usage/Access values from the 31,777-block population inventory (16 representative samples):

| Pattern | Usage | Role | Status |
|---|---|---|---|
| `37040300` | usage=1 | position/normal/UV (role-agnostic) | **MAPPED** |
| `36040200` | usage=1 | float vertex data variant | Family-mapped |
| `15020100` | **usage=0** | **Index stream descriptor** | **CORRECTED** |
| `10010400` | usage=1 | Vertex data descriptor | Family-mapped |
| `3c010400` | usage=1 | Vertex data descriptor | Family-mapped |

### Key finding: `15020100` = index stream descriptor
Previously classified as "u16-vertex-data family" (byte-0 fallback, M4.2). Cross-reference reveals it appears with `usage=0/access=19` (index data), not `usage=1` (vertex data). This is a significant semantic correction — `15020100` is an index stream descriptor, not a vertex data descriptor. Evidence is at sample scale (n=16); population-scale validation would require a new CLI command.

### Gate 2 assessment
- **Before M8.2**: 1/5 patterns with role evidence, 3/5 with no role indication
- **After M8.2**: 5/5 patterns with usage-level evidence, 1 index-identified, 3 family-mapped
- **Remaining gap**: Role specificity — "position" vs "normal" vs "UV" for individual patterns beyond `37040300`
- **Status**: blocked (improved) → **improved (usage-level evidence)** — not yet CLEARED
