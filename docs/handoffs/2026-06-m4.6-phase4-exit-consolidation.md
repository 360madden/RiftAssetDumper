## Part 1: M4.1 — Byte-3 Integrity Check

**Location**: `AnalyzeNifDataStreamLayout` (Program.cs ~line 9740)
**Type**: Passive warning

### What was built
After extracting `rawDescriptorBytes` (4 bytes at offset 24), checks `blockPayload[27] != 0x00`. If non-zero, appends `"descriptor-byte-3-nonzero"` to the layout warning.

### Why this was first
- **Smallest possible behavioral change** — single byte check, single warning
- **Best-proven evidence** — byte-3 = 0x00 universal across 184/184 sampled blocks (Phase 2)
- **Safety-first** — warns on unexpected data without blocking processing

### Verification
- 2 xUnit tests: positive (byte-3=0xFF → warning) and negative (byte-3=0x00 → no warning)
- Scale verification: `inventory-nif-stream-headers --max-total 200` → 375 blocks, **0 byte-3 non-zero warnings** (universal invariant confirmed)

## Part 2: M4.2 — Byte-0 Fallback Classification

**Location**: `ClassifyNifDescriptorByByte0()` (Program.cs ~line 10811)
**Type**: Classification coverage expansion

### What was built
New method extracts first 2 hex chars (byte-0) and classifies into 5 family labels:

| Byte-0 | Family Label |
|---|---|
| `37` | `ror1-float family (byte0=0x37)` |
| `36` | `float-vertex-data family (byte0=0x36)` |
| `15` | `u16-vertex-data family (byte0=0x15, candidate)` |
| `10` | `unknown family (byte0=0x10, candidate)` |
| `3c` | `unknown family (byte0=0x3c, candidate)` |

### Integration
Wired as `_ => ClassifyNifDescriptorByByte0(descriptorBytes)` fallback in `ClassifyNifDescriptor`. Unknown full 4-byte patterns now get family-level labels instead of `null`.

### Verification
- 4 xUnit tests: known byte-0 values, unknown byte-0, fallback integration, null/empty guards
- Scale verification: 16/16 sample records classified, **0 nulls** (100% coverage)

## Part 5: M4.5 — Descriptor-Role Cross-Check

**Location**: `CheckDescriptorRoleConsistency()` + `ProbeNifMesh` (Program.cs ~line 1966)
**Type**: Active warning (first behavioral consumption)

### What was built
- `CheckDescriptorRoleConsistency(primaryRole, descriptorClassification)` — compares stream role against descriptor family
- Classifies roles as float (`position*`, `normal*`, `uv*`) or index (`index*`)
- Classifies descriptors as float (`ror1-float`, `float-vertex-data`) or u16 (`u16-vertex-data`)
- Returns warning for mismatches: float role + u16 descriptor, or index role + float descriptor
- Unknown descriptor families → no check (returns null)

### Integration
Warning loop in `ProbeNifMesh` after stream refs line iterates all `mesh.Streams`, calls `CheckDescriptorRoleConsistency`, prints `"WARNING: #block @offset: message"` for each mismatch.

### Verification
- 6 xUnit tests covering all branches:
  - Float role + float descriptor → null
  - Index role + float descriptor → warning
  - Float role + u16 descriptor → warning
  - Null role → null
  - Null descriptor → null
  - Unknown descriptor family → null
- 29/29 tests pass
