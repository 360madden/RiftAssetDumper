# Cycle 5.2 — Zone Field Confidence Tightening (2026-06-28)

## Goal

Tighten the per-asset zone field by **recording First4 magic for transparency**
(verifying it does NOT discriminate siblings from coincidental neighbors) and
**adding a `zone_confidence` tier** (high/medium/low based on |delta|) so
consumers can opt out of low-confidence attributions.

## Rationale (First4 does NOT discriminate)

The archive-neighbor verification handoff (`docs/handoffs/2026-06-28-archive-neighbor-verification.md`)
empirically confirmed that for the 5 closest and 3 farthest Δ-1 archive
neighbors, **all 8 share the same First4 magic** (`47616d65`, standard Gamebryo
NIF magic). First4 alone therefore cannot discriminate a tight co-bundled
sibling from a coincidental neighbor. **Entry-Index Δ is the discriminating
signal.**

First4 is therefore:

- **recorded** as the `first4` / `zone_first4` field (lowercased 8-hex string)
  for transparency
- **NOT used** as a filter — the resolution still uses Entry-Index Δ
- **documented as non-discriminative** in:
  - the v2.json top-level `first4_rationale` prose string
  - the v2.json boolean `first4_discriminates: false` (machine-readable)
  - the `scene-manifest-v1.schema.json` Zone.first4 description

## Cross-repo propagation (7-step pipeline)

1. **`scripts/build_fly_asset_zone_map.py`** — Per-asset zone map from
   `zone-full.json` + archive-neighbor fallback. Now emits:
   - per-entry: `tuple`, `expansion`, `category`, `name`, `method`, `delta`,
     **`first4`**, **`confidence`**
   - top-level adds: `confidence_distribution`, `expected_first4`,
     **`first4_discriminates`**, `first4_rationale`, `neighbor_window`

2. **`scripts/inject_zone_into_flythrough_index.py`** — Forwards new fields
   from v2.json into `flythrough-index.json` zone records. 229/229 populated.

3. **`scripts/build_scene_manifest.py::build_zone()`** — Reads the same new
   fields from flythrough-index into stage6 manifests' `zone` block.
   229/229 stage6 manifests carry `first4` + `confidence`.

4. **`docs/schemas/scene-manifest-v1.schema.json`** — Zone $def extended:
   - `first4`: string, pattern `^([0-9a-f]{8})?$` (canonical nullable-group
     form — exactly 8 hex chars OR empty string)
   - `confidence`: enum `["high", "medium", "low"]`
   - Description documents the **delivery-side naming convention**:
     `zone.first4` (schema) ↔ `zone_first4` (delivery-top-level).

5. **`scripts/build_riftflythrough_delivery.py`** — Forwards manifest `zone`
   block fields into delivery top-level prefixed keys (`zone_first4`,
   `zone_confidence`, etc.) plus per-confidence summary stats.

6. **`C:/RIFT MODDING/RiftFlythrough/js/transform_loader.js`** —
   `RiftZoneRegistry` exposes `getZone()` (returns confidence + first4) and
   `getZoneStats()` (counts per confidence tier).

7. **`C:/RIFT MODDING/RiftFlythrough/js/catalog.js`** — Per-row confidence pill
   (high = green, medium = amber, low = red, mismatched = dim).

## Audit-key correctness finding (from prior cycle)

`ArchiveProvenance` is a Python `NamedTuple` in `synthesize_semantic_matrices.py`,
destructured per `docs/schemas/asset-semantic-index-v1.schema.json` into
`ArchiveName` + `EntryIndex`. Always address these fields directly:
`entry["ArchiveName"]` + `entry["DetectedType"]` + `entry["MagicLabel"]`.
Naive `entry.get("ArchiveProvenance")` will always return `None`.
