**Result**: 16/16 (100%). Zero conflicts. The stride→usage rule is validated: **uint16×scalar → index, everything else → vertex**.

### Why Dual Validation Matters

The stride divisibility test (M9.1) is **structural**: it proves the math works. The usage consistency test (M9.3) is **semantic**: it proves the math maps to real-world stream roles. These are independent — a valid stride does not guarantee correct usage, and correct usage does not guarantee valid stride. That both pass 16/16 with zero conflicts is exceptionally strong evidence.

## Part 4: The Stride→Usage Rule

The most significant finding from the dual validation is a proven invariant:

> **uint16×scalar (byte-1=0x02, byte-2=0x01) → usage=0 → index stream**
> **All other element types → usage=1 → vertex data**

This rule is:
- **Derived purely from descriptor bytes** — no usage-level training data needed
- **Correct on 16/16 samples** — zero exceptions
- **Architecture-consistent** — the descriptor describes the stream body, and the body type determines the usage

This rule closes the loop between the structural stride hypothesis (M9.1) and real-world stream semantics (M8.2). The descriptor bytes alone encode the fundamental index-vs-vertex distinction.

## Part 5: Internal Consistency

Beyond the validation dimensions, the semantic map is internally consistent:

1. **Byte-0 families align with roles**: `ror1-float` → position/normal/UV (3-component float data), `index-data` → index stream (integer data), `float-vertex-data` → UV (2-component float data)

2. **No contradictions**: No pattern with a specific role assignment shows conflicting evidence. `15020100` has usage=0 on all 3 samples. `36040200` has usage=1 on all 2 samples. `37040300` has usage=1 on all 8 samples.

3. **The role-agnostic pattern (`37040300`) is correctly characterized**: It serves position, normal, and UV — confirmed in Phase 2 binding proofs. The descriptor family label (`ror1-float`) is intentionally role-agnostic.

4. **The `10010400`/`3c010400` distinction is a sub-family refinement**: Both are 4-byte packed vertex attributes at the family level. They differ in byte-0 sub-type (0x10 vs 0x3c) — likely signed/unsigned or attribute type. This is a data-level probing question, not a semantic mapping gap.
