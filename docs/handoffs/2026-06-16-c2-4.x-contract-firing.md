## Per-asset manifest run (C2-4.1 — `stage 4.1`)

### What runs

For each of the **24 cohort asset IDs** (4 non-id + 20 distinct id per `transform-examples.json`), produce a per-asset manifest that:

1. Uses the **V4-locked schema** (not the draft).
2. Pulls world transforms from `Assets/build/flythrough/objs/worlds/<asset_id>.world.json`.
3. Pulls **both** texture sources:
   - `textures.source = "scene"` from the scene-manifest builder's read of the world.json sidecar.
   - `textures.source = "flythrough"` from `Assets/build/flythrough/flythrough-index.json`'s `assets[asset_id].linked_textures`.
4. Sets `consumer_ready = true` **iff** (per C2-3.1 M3 recommendation to V4 Pro):
   - `textures.source` is set to a known value (not `"unknown"`);
   - `geometry.face_count > 0` OR `geometry.render_class` is genuinely `"pos_only"` (textureless surfaces are valid);
   - `consumer_ready` is `false` if either source is missing or stubbed.

### How it runs

Reuse the existing `scripts/build_scene_manifest.py` (already validated in
C2-2.4 / commit history) with **one config change**: the schema path must be
changed from `scene-manifest-v1.draft.schema.json` to `scene-manifest-v1.schema.json`.

The cleanest path is a small edit to `build_scene_manifest.py`:

```python
SCHEMA_PATH = (
    REPO_ROOT
    / "Assets"
    / "Exports"
    / "discovery-plan"
    / "cycle-2"
    / "stage2"
    / "scene-manifest-v1.schema.json"   # was: .draft.
)
```

After that edit, run:

```bash
python scripts/build_scene_manifest.py --all-non-id --validate-only    # validate
python scripts/build_scene_manifest.py --all-non-id                     # regenerate 4 non-id
# 20 distinct id assets regenerated via:
for aid in $(python -c "from build_scene_manifest import find_id_asset_ids; print(' '.join(find_id_asset_ids()))"); do
    python scripts/build_scene_manifest.py --asset-id $aid
done
```

The M3 handoff for C2-5.x will be drafted as a follow-on **after** C2-4.1
lands. Don't draft it now — V4P12 may add fields that change C2-5.x's expected
shape.

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| V4P12 returns with a schema that doesn't include `textures.source` | M3 has documented this as the highest-priority gap; if V4 defers, M3 can still run C2-4.x but MUST record `textures.source: "unknown"` for all 24 assets and explicitly mark `consumer_ready: false` until V4P3 addresses. |
| V4P12 output is malformed / unparseable | Stop at pre-flight gate; report schema error to operator before proceeding. Do not silently fall back to draft schema (which would invalidate the locked-schema claim). |
| Some cohort assets lack world.json (haven't been materialized into the live flythrough mirror) | Build manifest with `world: {world_transform_summary: null, world_transform_identity: true}` and `provenance.note: "world.json missing; using empty/neutral markers"`. Consumer runtime should treat missing world.json as a deliberate placeholder, not an error. |
| coverage of <24 manifests because of source data drift | If <24 cohort assets have valid (asset_id, world.json, flythrough entry) tuples, surface the gap; C2-4.x cannot hit 24/24 if upstream data is missing. |
