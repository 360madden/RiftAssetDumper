### Critical finding: Descriptor is per-block embedded

**The descriptor is NOT a static table.** It is 4 bytes embedded at offset 24 in each NiDataStream block header.

| Evidence | Source |
|---|---|
| All Ghidra static-table bytes are zero | Base-model review |
| 184 ShiftedSamples each have 4 descriptor bytes at offset 24 | Layout report |
| 5 distinct patterns observed across 184 blocks | Layout report |
| Byte-3 always 0x00 (184/184) | Layout report |

### 5 Descriptor Byte Patterns

| Pattern | Count (of 184) | % | Known Semantic |
|---|---|---|---|
| `37 04 03 00` | 90 | 48.9% | **Generic ror1-float** (position, normal, UV) |
| `36 04 02 00` | 49 | 26.6% | **Float-vertex-data** (resolved June 2026) |
| `15 02 01 00` | 23 | 12.5% | **Unknown** — appears at blocks 23/26/35/70/101/130 |
| `3c 01 04 00` | 14 | 7.6% | **Unknown** — plausible index/list |
| `10 01 04 00` | 8 | 4.3% | **Unknown** — plausible index/strip |

### Key reinterpretation

Byte-0 was previously labeled "static table index" in `nidatastream-descriptor-proof-status`. M2.1's per-block-embedded finding challenges this: byte-0 is an **inline descriptor field** — a stream-type enumerator — not a table lookup index.

- 10 blocking items in descriptor-sample-compare (none resolved)
- Semantic mapping false; 1/3 fields mapped; 4 candidate entries
- `FieldOrderPromoted` = false (confirmed, must stay false)
