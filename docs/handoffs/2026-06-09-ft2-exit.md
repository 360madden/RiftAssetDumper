## Key design decisions

1. **`--use-probe-lookup` flag**: Uses `Exports/probe-meshsize-lookup.json` keys as asset ID list (56 entries with known mesh_block values). The default `--inventory` path uses `nif-mesh-binding-inventory.json` but overlap is only 2 entries.

2. **Two-pass decode**: Tries `--export-obj` (attribute-set @264 indexed, faced OBJs) first. On "no attribute sets", falls back to `--experimental-position-source --write-obj` (fan faces, pos-only fallback).

3. **Mesh-block retry chain**: If the probe lookup's mesh_block fails with "not found", tries `[6, 7, 8, 9, 10, 27, 31, 25, 17, 0]` in order.

4. **`--out` directory**: Each asset gets `out_dir/decode-nif-geometry-<id>/` as the C# output target. The C# command creates a nested `decode-nif-geometry/` subdirectory with `decode-nif-geometry-mesh<N>.obj`.

5. **Failure manifest entries**: Failed assets write diagnostic entries to the manifest (not just the errors list), enabling offline triage.

## Known limitations

1. **Probe lookup is stale**: Built from Phase 27-45 probes on the deleted `Source/` directory. 49/56 entries lack decodable position data in the live archive.
2. **No sibling pairing**: This driver doesn't handle cross-mesh sibling position pairing (float2 meshes needing float3 siblings for Z). That's `batch_export_sibling.py`'s job.
3. **Position-only exports lack faces**: 4/7 successful exports are vertex-only. The experimental fallback path produces fan faces from vertex 0 but only when position data is genuinely decodable.
4. **`load_asset_ids_from_inventory` overlap**: Only 2 entries overlap between `nif-mesh-binding-inventory.json` and `probe-meshsize-lookup.json`. A fresh inventory build is needed for broader coverage.
