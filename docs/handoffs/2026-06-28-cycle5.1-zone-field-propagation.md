# Cycle 5.1 — Zone Field Propagation (handoff)

**Date:** 2026-06-28
**Author:** Buffy
**Scope:** Enrich `flythrough-index.json` with a per-asset zone field and ship to RiftFlythrough via the practical access layer.

## TL;DR

Added a `zone` sub-record to every fly asset, threaded it through `build_scene_manifest.py` → `build_riftflythrough_delivery.py` (v0.4), and locked the schema in `scene-manifest-v1.schema.json`. The zone tuple (e.g. `vanilla.world_objects.props`) is the canonical identifier; the `method` field discriminates how the attribution was derived (`direct` = own NIF in `zone-full.json` carries the path; `neighbor` = closest path-bearing NIF in same archive within ±150; `unmatched` = no path-bearing NIF in window).

**Key numbers** (from `build_fly_asset_zone_map.py`):

- 229 fly assets total
- 164 (72%) `method=direct` (asset's own NIF in `zone-full.json` carries the path)
- 65 (28%) `method=neighbor` (resolved via ±150 archive-neighbor)
- 0 (0%) `method=unmatched` — all 229 resolved at the flythrough-index level

**Top zones**: Housing (73), Nature (45), Character Common (25), Atmosphere (24), Architecture (20).

## What was added

### 1. `Assets/build/flythrough/flythrough-index.json`

Each of the 229 assets now has a nested `zone` sub-record:

```json
"zone": {
  "tuple": "vanilla.world_objects.props",
  "expansion": "vanilla",
  "category": "world_objects",
  "name": "props",
  "method": "direct" | "neighbor" | "unmatched",
  "delta": 0
}
```

### 2. `docs/schemas/scene-manifest-v1.schema.json` (updated)

- Added `Zone` `$def` with `tuple` / `expansion` / `category` / `name` / `method` / `delta`
- Added optional `zone` property at the root (parallel to the existing optional `semantic` block)
- `method` enum: `["direct", "neighbor", "unmatched"]`
- `expansion` enum: `["vanilla", "ep1", "ep2", "ep3", null]`
- `delta`: `["integer", "null"]` with `minimum: 0` (always non-negative; the parser uses `abs(ei − target_ei)`)
- Description updated to note the Cycle 5.1 addition

### 3. `scripts/build_fly_asset_zone_map.py` (new, ~140 lines)

Re-derives the per-asset zone map from `zone-full.json` with two methods:

- **Direct match** (164/229): the fly asset's own NIF entry in `zone-full.json` carries a parseable `Z:/TWN/art/project/...` path. The path is parsed into `expansion`/`category`/`zone`/`tuple` per the multi-segment rules in the v2 cross-ref.
- **Archive-neighbor** (65/229): for assets without direct path metadata, scan the same archive for the closest path-bearing NIF within ±150 entry indices. Distance recorded as `delta`.

Path extraction handles both raw paths (`Z:/TWN/art/project/...`) and the prefixed form (`NIF Creation Information >> Z:/TWN/art/project/...`) found in NIF `TextSnippetSamples`.

Output: `Exports/semantic-phase1/fly_asset_zone_map_v2.json`.

### 4. `scripts/inject_zone_into_flythrough_index.py` (new, ~50 lines)

Loads the zone map and injects the `zone` sub-record into each of the 229 assets in `flythrough-index.json`. In-place rewrite preserves all other fields.

### 5. `scripts/build_scene_manifest.py` (updated)

Added `build_zone(flythrough_entry)` that copies the zone sub-record from the flythrough-index entry into the stage6 manifest. When the flythrough entry has no zone (e.g., the 4 non-id cohort assets that bypass flythrough-index), the fallback is `method='unmatched'` with null fields.

### 6. `scripts/build_riftflythrough_delivery.py` (updated to v0.4)

- Added 6 zone fields to each delivery entry: `zone_tuple`, `zone_expansion`, `zone_category`, `zone_name`, `zone_method`, `zone_delta`
- Added zone stats to `build_stats()`: `zone_tagged_assets`, `distinct_zones`, `zone_distribution`, `zone_method_distribution`
- Markdown report includes a Zone column in the per-asset detail table
- Bumped to v0.4 with a "What changed" changelog entry

## Finding: 6 vs 153 consumer_ready regression (PRE-EXISTING, not caused by zone changes)

**The delivery only ships 6 consumer-ready assets (down from the previous 153/217).** This is **NOT** caused by the zone field changes — it's a pre-existing data population issue:

- `build_textures()` reads `flythrough_entry.get("linked_textures")` to set `texture.source`
- For 229/229 fly assets, `linked_textures` is **absent** from `flythrough-index.json` (verified by diagnostic)
- The 6 consumer_ready assets retain `textures.source='flythrough'` from a previous build (when the field was populated differently or the build path was different)
- The other 223 have `textures.source='unknown'` because `linked_textures` is missing → `consumer_ready=False` (the check requires `textures.source != "unknown"` AND `textures.linked_texture_count > 0`)

**Fix for next session**: populate `linked_textures` in `flythrough-index.json` for all 229 assets (the `link_flythrough_textures.py` script likely does this but was not re-run after the last flythrough-index write). Then re-run `build_scene_manifest.py --all-flythrough` to restore 153/217 consumer_ready.
