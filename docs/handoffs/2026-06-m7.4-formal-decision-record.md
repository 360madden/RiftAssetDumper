## Gate 5 Evaluation: Pairing Impact Proof

### Current status

Gate 5 requires demonstrating that "a parser interpretation change improves complete position+normal+UV evidence without promoting noise." The M6.2 evaluation found this gate "candidate (strongly strengthened)" citing 3 levels of descriptor-guided pairing but blocked by the attrSets=0 architectural constraint.

### Cumulative evidence (Phases 2-7)

| Level | Mechanism | Milestone | Evidence |
|---|---|---|---|
| 1. Confidence scoring | `AdjustConfidenceByDescriptor()`: +5 float match, -10 u16 mismatch | M5.2 | 10 tests; capped/floored; additive not multiplicative |
| 2. Candidate prioritization | `IsFloatDescriptor()` boost sorting in position pre-filter | M5.3 | Behind `--experimental-position-source` gate; float-family candidates preferred |
| 3. Validation warnings | `CheckDescriptorRoleConsistency()` + Usage/Access enrichment | M4.5, M5.4 | Warns on float/u16 mismatches; `usage=X access=Y` context |
| 4. Export validation | `ValidateDescriptorExportPrechecks()` in OBJ export | M6.3 | 8 tests; structural + descriptor alignment warnings |
| 5. Export metadata | `# Position descriptor:` comment in .obj files | M6.1 | Both export paths covered |

**Cumulative milestone count**: Phase 2 (5) + Phase 3 (5) + Phase 4 (6) + Phase 5 (4) + Phase 6 (3) + Phase 7 (4) = **27 milestones** across Phases 2-7.

### Architectural constraint (attrSets=0)

The `attrSets=0` pattern on sibling meshes (#34 variants in 329 family, confirmed cross-family in 305) means no mesh has all 4 attributes (position + normal + UV + index) simultaneously. This is NOT a descriptor gap — it is the game's architectural design:

- Mesh#7: attrSets=1, complete bindings (position @212 + normal + UV + index)
- Mesh#34: attrSets=0, partial bindings (position @212 only; @304 is position-like but not attr-extra)
- Pattern confirmed: 12/12 329-family pairs, 3/3 305-family pairs

The gate's original criterion — "complete position+normal+UV evidence" — is structurally impossible given the game's architecture. All 94 OBJ exports to date work with partial bindings.

### Reframing recommendation

**Recommendation**: Reframe gate 5 from "improves complete geometry groups" to "improves available geometry evidence given the architectural constraint." Under this reframing:

| Criterion | Current evidence | Assessment |
|---|---|---|
| Descriptor data improves pairing quality | 3 levels of guided pairing (M5.2-M5.4) | ✅ Pass |
| Descriptor data does not promote noise | All changes are candidate-only or behind gates; 0 decode/export changes | ✅ Pass |
| Pairing evidence is at the best available level | attrSets=0 is architectural, not a gap; no complete groups exist in game | ✅ Architecture accepted |

**If reframed**: Gate 5 would **CLEAR** on current evidence. This would be the 4th gate clearance in Phase 7.

**Risk assessment**: Low. Gate 5 reframing does not change any code. It acknowledges that the game uses partial bindings by design and that descriptor-guided pairing is the best available evidence. Gate 6 (safety brake) remains held, so no parser/export code can change without explicit approval.

**Deliberate restraint**: This decision record does NOT force gate 5 clearance. It documents the evidence and recommends reframing. The final decision is left to human review. In the autonomous lane, gate 5 remains "candidate (strongly)" — the reframing is documented but not actioned as a clearance.
