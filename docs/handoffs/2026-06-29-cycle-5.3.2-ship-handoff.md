## 2. What landed in cycle-5.3.2 (closes the F4 deferred nits)

### F4 nit #1 — cancellation propagation (`scripts/ghidra/ScalarOffsetSearcher.java`)

3 cancel-narrowings added. Before each `catch (Exception ex)` block in the per-hit region, an explicit `catch (CancelledException ce) { throw ce; }` rethrow now precedes the broader handler. Sites:

1. **Bytes-fetch** (`currentProgram.getMemory().getBytes(...)`) — LATE-DISCOVERED 3rd site. Original F4 review only flagged context walks; cancel-during-bytes-read was a previously-leftover latent bug fixed in this cycle.
2. **Prev-context walk** loop body — `Address prevAddr = addr;`.
3. **Next-context walk** loop body — `Address nextAddr = addr;`.

`import ghidra.util.exception.CancelledException;` added at L18.

### F4 nit #2 — per-hit folded summary

- Removed both per-failure inline printerrs (`"failed to walk previous context near ..."` / `"failed to walk next context near ..."`).
- New per-hit accumulator `List<String> contextWarnings = null;` declared at the start of the per-hit region.
- Both walks `add(...)` their failure entries into the same list (`"previous:<FQCN>:<msg>"` / `"next:<FQCN>:<msg>"`).
- After both walks complete, emit exactly ONE printerr per hit: `"WARN: scalar-offset-search partial context at <addr> (<joined contextWarnings>)"` using `String.join("; ", contextWarnings)`.
- FQCN parity restored: `getClass().getName()` (not `getSimpleName()`) for consistency with the rest of the cycle-5.3.1 polish batch.

### Test fixture — `tests/test_ghidra_cancellation_propagation.py` (NEW, 10 tests)

Static-analysis pytest fixture. Ghidra's analyzeHeadless can't run in CI, so we read the `.java` as text and lock the structural patterns that prove both F4 nits' intent.

**Architecture: inverted-anchor** — each narrowing-position test searches FORWARD from a known anchor (`Address prevAddr = addr;` / `Address nextAddr = addr;` / `currentProgram.getMemory().getBytes(`) and asserts that the cancel-catch (the structural marker we care about) appears AFTER the anchor. Robust against future loop-body growth (currently ~1200 chars to `throw ce;` in the prev-walk body).

**Plus an inter-catch ordering-guard test** that asserts `bytes_fetch_catch < prev_walk_catch < next_walk_catch` — disambiguates which catch belongs to which walk in malformed files (where one cancel-catch could be re-counted for multiple walks).

**Negative regressions enforced:** old `"failed to walk previous context"` / `"failed to walk next context"` strings MUST be absent.
**Discriminator prefix enforced:** `"scalar-offset-search partial context"` MUST be present (downstream grep-stability).
