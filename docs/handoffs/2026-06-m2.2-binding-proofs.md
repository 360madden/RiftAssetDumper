## Part 1: 329 Family Binding Proofs

### Binding Proof Schema

```
BindingProof {
  NifId: hex16,
  MeshBlock: int,       // NiMesh block index
  AttributeIndex: int,  // 0=position, 1=normal, 2=UV, ...
  StreamBlock: int,     // NiDataStream block index
  StreamOffset: int,    // mesh payload offset within stream
  Role: string,         // classified role
  Confidence: int,      // 0-100
  DescriptorBytes: hex, // 4 bytes at stream block offset 24
  EvidenceSource: string // "matrix", "probe", "family-proof"
}
```

### Binding Pattern Analysis

**Key structural finding**: In the 329 family, mesh#7 and mesh#34 share the **exact same NiDataStream block** (#28) for position data. The binding is:

```
NiMesh(block=#7, attr=Position) → NiDataStream(block=#28, offset=@212)
NiMesh(block=#34, attr=Position) → NiDataStream(block=#28, offset=@212)
```

This is a **source-binding reuse** pattern: two distinct mesh blocks consume the same position stream. The siblings diverge in their secondary bindings:

- mesh#7 consumes block #36 (UV) at @304
- mesh#34 consumes block #57 (anomalous position-like) at @304

### Descriptor Cross-Reference

All primary bindings (position, normal, UV) target blocks with descriptor `37 04 03 00`:

- Block #28 (position): `37 04 03 00` ✅ — ShiftedSamples
- Block #29 (normal): `37 04 03 00` ✅ — ShiftedSamples
- Block #36 (UV, #7): `37 04 03 00` ✅ — ShiftedSamples

This confirms: `37 04 03 00` is the universal descriptor pattern for ror1-float data streams, regardless of whether they carry position, normal, or UV data. The descriptor does **not** encode per-attribute semantics — those come from the NiMesh→NiDataStream binding relationship, not from the descriptor bytes.

### Universal binding patterns (both families)

1. **Position source-binding reuse**: sibling mesh blocks share the same NiDataStream position block
2. **Descriptor uniformity**: all ror1-float position streams carry `37 04 03 00`
3. **Secondary divergence**: siblings diverge in secondary stream bindings (different blocks, different roles)

### Divergent binding patterns (family-specific)

1. **Secondary role**: 329 sibling has anomalous position-like extra stream; 305 sibling has genuine UV
2. **Secondary block layout**: 329 uses block #57 for extra; 305 uses block #40 for UV
3. **Mesh block distance**: #34 is 5 blocks from #7 in 329; #27 is closer in 305

## Human-Readable Summary (M2.2 Entry)

**What this milestone does**: Formalizes the NiMesh→NiDataStream binding proofs at scale using Phase 1's family proof data. Documents that position blocks (#28 in 329, #21 in 305) are shared between sibling mesh variants — a consistent source-binding reuse pattern. Confirms that all ror1-float streams (position, normal, UV) carry the same descriptor pattern `37 04 03 00` — descriptor bytes do not encode per-attribute semantics.

**Why it matters**: Binding proofs are the bridge between Phase 1's stream role classification and Phase 3's parser implementation. They establish which NiDataStream block feeds which mesh attribute, enabling targeted descriptor field mapping (M2.3) and parser integration (Phase 3).

**What remains**: Descriptor bytes for anomalous blocks (#55, #57) are unverified. Complete geometry binding for attrSets=0 siblings remains blocked. Scale validation beyond the 12 matrix IDs is pending `inventory-nif-mesh-bindings`.
