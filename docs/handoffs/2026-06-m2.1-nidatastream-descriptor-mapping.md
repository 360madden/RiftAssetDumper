> **M2.1**: Complete field-order + semantic mapping for high-priority NiDataStream descriptors using Ghidra + sample bytes.

This milestone uses Phase 1's classified stream roles as **ground truth** to constrain Ghidra descriptor field mapping. Rather than blind stride/base sampling, we ask: given a stream known to be `position-float3-ror1-lead` at @212 with 48 float3 vectors and 576 bytes, what descriptor fields must exist to encode this? The answer constrains which Ghidra static table fields map to which stream semantics.

### Cross-Reference: Phase 1 Anchor Streams vs Descriptor Patterns

The layout report shows 5 descriptor byte patterns across 184 blocks. Cross-referencing with Phase 1's top stream roles (from `knowledge.md`) and the per-block ShiftedSamples evidence:

| Phase 1 Role | Occurrences | Candidate Descriptor Pattern | Evidence |
|---|---|---|---|
| position-float3-ror1-lead | 210 | `37 04 03 00` | **Direct**: block #28 (position anchor) shows `37 04 03 00` in ShiftedSamples |
| normal-float3-ror1-lead | 4,167 | `37 04 03 00` | **Direct**: block #29 (normal anchor) also shows `37 04 03 00` |
| uv-float2-ror1-lead | 4,633 | `37 04 03 00` | **Direct**: block #36 (UV anchor) also shows `37 04 03 00` |
| index-u16be-strip-lead | 2,101 | `10 01 04 00` / `3c 01 04 00` | **Indirect**: single-component uint patterns (byte 1=0x01, byte 2=0x04) consistent with index format |
| anomalous @304 (#34) | 12 | `15 02 01 00` | **Speculative** — block #57 (anomalous @304 anchor) NOT in ShiftedSamples; `15 02 01 00` observed at blocks 23/26/35/70/101/130 (none mapped to known Phase 1 anchor roles) |

**Corrected hypothesis**: `37 04 03 00` is a **generic ror1-float-stream descriptor** — it does not distinguish between position, normal, or UV. Role differentiation comes from other NiDataStream header fields (Usage, Access) or a runtime-built static table that maps the byte-0 index to specific semantics. Bytes 1-2 encode format/class variants (0x04/0x03 = generic float, 0x02/0x01 = specialized position, 0x01/0x04 = single-component uint). **Note**: `3c 01 04 00` has only 1/50 ShiftedSamples (14/184 in full population) — statistically weak compared to the dominant `37 04 03 00`.

### ShiftedSamples Per-Block Descriptor Analysis

The layout report's `ShiftedSamples` (50 samples) confirms that descriptor bytes ARE present in the NIF files — they are **embedded in each NiDataStream block header** at offset 24, not in a separate static table:

| Pattern | Count | Block indices (sample) | Interpretation |
|---|---:|---|---|
| `37 04 03 00` | 24/50 | 27, 28, 29, 30, 36, 37, 38... | Most common; likely represents generic ror1-float3 streams (position + normal + UV) |
| `36 04 02 00` | 14/50 | 31, 41, 42, 43, 76, 77... | Second most common; possibly index or packed data streams |
| `15 02 01 00` | 7/50 | 23, 26, 35, 70, 101, 130... | Third pattern; possibly the anomalous @304 position stream or specialized format |
| `10 01 04 00` | 4/50 | 40, 75, 106, 135... | Single-component uint format (byte 1=0x01, byte 2=0x04) — likely index streams |
| `3c 01 04 00` | 1/50 | 26 | Rare; single-component uint variant |

**Key insight**: The descriptor is **per-block embedded** (4 bytes at offset 24 of each NiDataStream block header), NOT a static lookup table. This is consistent with Ghidra's finding that the static image bytes are all zero — the table doesn't exist as a separately-allocated structure. The descriptor bytes travel with each stream block.

### Synthesis: What This Means for M2.1

1. **No static table to sample**: Ghidra's stride-12 hypothesis is addressing a non-existent static table. The all-zero result is EXPECTED — the descriptor data is in the block headers, not in a static allocation.
2. **Descriptor is per-block**: Each NiDataStream block has its own 4-byte descriptor at offset 24. Phase 1 anchor streams can be directly mapped to their descriptor bytes by reading the NIF block headers.
3. **5 consistent patterns**: Despite being per-block, the descriptors show only 5 distinct patterns across 50 samples — this means they encode a limited set of stream type configurations, not per-stream custom data.
4. **Byte 3 always zero**: Confirmed across all 184 blocks (layout report) and all 50 ShiftedSamples — consistent with padding/sign-guard.
5. **M2.1 path forward**: Instead of debugging Ghidra's static table stride, extract descriptor bytes directly from Phase 1 anchor NIF block headers, cross-reference with known stream roles, and validate the 5-pattern mapping hypothesis.
