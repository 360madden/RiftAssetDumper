### Shared Patterns (cross-family)

1. **attrSets=1 on #7, attrSets=0 on sibling** — both families repeat this pattern; suggests a deliberate mesh variant scheme where the #7 block carries the complete attribute set and the sibling (#34 or #27) is a stripped variant
2. **Shared primary position stream** — in both families, #7 and the sibling share the exact same position data (same BodyFirst16), confirming source-binding reuse
3. **Sibling has different secondary stream** — in both families, the sibling's @196 (305) or @304 (329) stream differs from #7's secondary stream — the sibling always substitutes something different
4. **Both families blocked from export** — attrSets=0 on the sibling means no attribute-extra path; parser/export promotion blocked

### Divergences (family-specific)

1. **Sibling secondary role**: 329's #34 @304 is an anomalous position-like stream (c=75, low plaus ~0.4, ~0.4× size, distinct bodies); 305's #27 @196 is genuine UV data (c=80, UV-range unit vectors). The 305 sibling has a cleaner secondary stream.
2. **Secondary stream resolution**: 329's @304 remains candidate-only with detailed quant from M1.2; 305's @188 was probed deeper in the post50 cycle and confirmed negative (residual classifier: magic-43606 ≠ position data; float32 decode = denormal garbage 10⁻²⁷ to 10⁻³⁹)
3. **Mesh block layout**: 329 uses #34 as sibling (5 mesh blocks apart from #7 by offset pattern); 305 uses #27 (much closer to #7)
4. **Secondary block target**: 329's sibling #34 targets a different block for @304 vs primary; 305's sibling #27 targets block#40 for UV@196 (different from #7's block#22 for NORMAL@196)
