## Bottom line

The C2-3.1 texture-coverage profiler (`scripts/build_texture_coverage.py`)
profiles all 24 cohort assets (4 non-id + 20 distinct id) and produces a
per-asset coverage matrix that compares:

- **scene-manifest `textures` block** (source from C2-2.4 sample-manifests,
  carries `linked_texture_count` / `linked_textures` / `missing_texture_count` /
  `placeholder_texture_count`);
- **flythrough-index.json `linked_textures`** (source from FT plan / Phase 21,
  carries a list[str] of PNG filenames per asset).

Across the 24-asset cohort:

| Metric | Count |
|---|---:|
| cohort_size | 24 |
| textureless (`scene.linked=0, scene.placeholder=0, fly>0`) | 24 |
| `covered` (`scene.linked>0`) | 0 |
| `partial` (`scene.placeholder>0`) | 0 |
| `missing-flythrough` (asset not in flythrough-index) | 0 |
| `missing-manifest` (scene-manifest missing) | 0 |
| **contradictions** (`scene.linked != fly.linked_count`) | **23** |
| **non-contradicted** (assertion holds) | 1 |

The single non-contradicted asset has both `scene.linked=0` and `fly.linked=0`.

### Reading the headline

**23 of 24 cohort assets (~96%) show a scene-manifest vs flythrough-index
texture count discrepancy**. This is **not** random — it is a structured
signal about the scene-manifest v1 draft schema's `textures` block.

The scene-manifest stage2 builder (`scripts/build_scene_manifest.py`,
pre-V4P12) populates its `textures` block from the
`Assets/build/flythrough/objs/worlds/<asset_id>.world.json` per-asset
sidecar, which carries `ParentNiNodeIndex` + transforms but **does NOT
carry texture bindings**. So the scene-manifest `textures.linked_texture_count`
is naturally 0 for the entire cohort — there is no source-of-truth for it.

Meanwhile, `flythrough-index.json` was populated by the FT plan (Phase 21) via
`build_flythrough_texture_map.py` + `link_flythrough_textures.py` from the
RiftFlythrough-ready linkage database. That database has 626 linked PNGs
across 207/217 flythrough assets (10 missing-texture gaps documented in
FT-1/FT-2 exit handoffs).

The 23 contradictions = the 23 cohort assets whose flythrough linkage is
populated and whose scene-manifest sidecar misses the texture data.

## What this implies for V4P12

The V4P12 brief at `docs/roadmap/cycle-2-briefs/block-1-transform-schema.md`
already contains the 4 schema gaps V4 Pro must resolve. The C2-3.1 finding
**changes the priority ordering** of these gaps:

| Gap | Original priority | C2-3.1 evidence | Revised priority |
|---|:---:|---|:---:|
| 6: `Geometry.vertex_count>0 && face_count>0` for `consumer_ready=true` | high | Not directly answered; sample-manifests already carry both fields for non-id cohort | **high** (still relevant) |
| 7: `Materials.scanned_at` timestamp | medium | Not contradicted; no Materials-time evidence in cohort yet | medium |
| 8: `geometry.obj_sha1` for cross-schema parity | medium | Not answered (geometry.obj_sha1 not yet emitted); FT-3 sidecar already has `obj_sha1` — parity work is queued | medium |
| 9: split `world.accumulated_transform` vs `declared_transform` | high | Not contradicted by C2-3.1 | **high** (still relevant) |
| **NEW (C2-3.1): add `textures.source` (manifest-style or flythrough-style)** | — | **23/24 cohort has 0 scene linked vs fly>0**; the schema's `textures` block has no documented "source" field — V4 Pro should consider whether to add `textures.source: "scene"\|"flythrough"\|"unknown"` so future runs don't conflate them | **highest** (mandatory before consumer_ready=true gating) |

### M3 recommendation for V4P12

1. **Add `textures.source` discriminant** to the v1 schema (string enum:
   `scene` / `flythrough` / `unknown`). This forces every scene-manifest
   `textures` block to declare its source-of-truth; future C2-3.x runs can
   honestly profile both sources separately.
2. **Move texture coverage to a `consumer_ready` precondition** —
   `consumer_ready=true` should require (a) `textures.source` is set to a
   known value AND (b) `linked_texture_count > 0 OR linked_textures is
   genuinely empty (textureless surfaces are valid)`.
3. **Keep the Geometry / Materials / world sub-gaps as-is** — the C2-3.1
   data doesn't surface additional noise in those subtrees.
