## Deliverables

### v0.8 NIF Material Property Scan

**New script:** `scripts/scan_nif_material_properties.py`

- Runs `dotnet run -- probe-nif --id <asset_id>` per asset
- Extracts `NiTexturingProperty`, `NiMaterialProperty`, `NiVertexColorProperty` block counts from `Header.BlockTypes[].NormalizedName` (case-insensitive matching via `.lower()`)
- Aggregates into `Assets/Exports/discovery-plan/cycle-2/stage3/material-scan-results.json` (`nif-material-scan-results/v1` schema)
- Supports `--cohort-only` (24 assets), `--limit N`, `--resume` (skip already-scanned)
- Strips `.world` suffix from cohort IDs (non-identity transform assets)
- Bug fixed: `NormalizedName` is PascalCase (`"NiMaterialProperty"`), not lowercase — scan script now lowercases before lookup

### build_scene_manifest.py v0.8

- `build_materials(asset_id, cohort_entry, flythrough_entry)` now accepts `asset_id` param
- `load_material_scan_results()` returns `(results_dict, scanned_at_timestamp)` tuple, cached at module level
- **Confirmed data path:** loads `material-scan-results.json`, populates `texture_property_count`, `material_property_count`, `vertex_color_property_count`, `scanned_at`
- **material_status from confirmed data:** `tex>0` → `"textured"`, `mat>0 or vc>0` → `"material-or-vertex-color-only"`, all zero → `"missing"`
- **Fallback:** if scan data absent, uses v0.7 inference from flythrough texture linkage
- `PRODUCER_VERSION` bumped to `v0.8`
