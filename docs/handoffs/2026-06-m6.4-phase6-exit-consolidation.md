## Part 3: M6.3 — Descriptor-Aware Export Pre-Checks

**Location**: `ValidateDescriptorExportPrechecks()` method + OBJ comment block + console output (Program.cs)
**Type**: Export validation (behind existing export gates)

### What was built

- `ValidateDescriptorExportPrechecks(string? positionDescriptor, int vertexCount, int faceCount)` — returns `List<string>` of warnings
  - **Structural checks**: zero vertices → early return; zero faces → warning; vertex count < 3 → warning
  - **Descriptor checks**: null descriptor → "unknown"; u16-family → mismatch warning; non-float, non-u16 → "unrecognized family"
  - **Float-family**: passes clean (no warnings)
- Integration at two points:
  - **OBJ comment block**: `# Export validation: CLEAN` or `#   WARNING: ...` lines written into `.obj` files
  - **Console output**: `Pre-export validation (N warning(s)):` summary before `OBJ written:` line
- Validation result stored once in `precheckWarnings` variable (DRY per code review)
- Uses existing shared helpers: `IsFloatDescriptor()`, `IsU16Descriptor()` from M5.2

### Verification

- 8 new xUnit tests covering all branches:
  - Zero vertices, zero faces, low vertex count
  - Null descriptor, u16 descriptor mismatch
  - Float descriptor (clean — no warnings)
  - Multiple warnings accumulated
- 49/49 tests pass total (M6.3 added 8 from 41 baseline)
- Code review: addressed indentation consistency and DRY call (single stored result)

### Design decisions

- Returns `List<string>` (not `string?`) — multiple independent checks may fire simultaneously
- All warnings are informational — no export is blocked
- Float-family descriptors are the expected norm; anything else triggers a warning
- Method is `internal static` for testability (consistent with `CheckDescriptorRoleConsistency` pattern)
