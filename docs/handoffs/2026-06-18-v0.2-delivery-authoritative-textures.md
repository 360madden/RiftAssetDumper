## Work Item 1: v0.2 Delivery Pipeline

### Problem

The v0.1 delivery JSON (`riftflythrough-delivery.json`) had three issues:

1. **Absolute Windows paths** leaked into `obj_path` and `world_json` fields — unreadable in-browser, privacy concern
2. **No resolved texture URLs** — the consumer (`world.js`) needs `textures/converted/<file>.png` URLs, but only raw `linked_textures` basenames were emitted
3. **`vv0.1` typo** in markdown output (doubled leading `v`)

### Solution

**Modified:** `scripts/build_riftflythrough_delivery.py` (v0.1 → v0.2)

**Key changes:**

| Feature | Implementation |
|---------|---------------|
| Path privacy | Dropped `obj_path`/`world_json` from emitted entries; replaced with `asset_id` + relative `obj_mesh` hint |
| Texture URL resolution | New `index_converted_textures()` + `resolve_texture_urls()` resolve `linked_textures` basenames to `textures/converted/<file>.png` |
| Hard guard | `_assert_no_absolute_paths()` aborts if any drive-letter path leaks into JSON output |
| `vv0.1` fix | `PRODUCER_VERSION` corrected to `v0.2` |
| Path bug | `CYCLE2_ROOT` factored out to fix `REPO_ROOT` double-prefix (`Assets/Assets/`) |

**Texture URL resolution logic:**

- `linked_textures` in `flythrough-index.json` already contains `.png` basenames (converted by `link_flythrough_textures.py`)
- `index_converted_textures()` maps lowercased `.png` basenames from `RiftFlythrough/textures/converted/`
- `resolve_texture_urls()` case-insensitively matches each basename, emits `{pattern: asset_id, url: "textures/converted/<file>.png"}` pairs
- Unresolved basenames are dropped from `linked_texture_urls` but retained in `linked_textures` for provenance
- **404/404 (100%)** resolution rate across all 153 consumer-ready assets

**New test suite:** `tests/test_build_riftflythrough_delivery.py` (5 tests)

- `test_help_exits_zero` — CLI smoke
- `test_build_smoke` — full build exits 0 (skipif no stage6 data)
- `test_emitted_json_has_no_absolute_paths` — no `C:\...` in JSON
- `test_emitted_json_contract` — v0.2 wire contract (SchemaVersion, no dead fields, URL shape, stats reconcile)
- `test_texture_url_resolution_is_nonempty` — ≥100 resolved URLs

## Knowledge Capture (for next session)

### Texture URL Resolution

- `linked_textures` in `flythrough-index.json` already contains `.png` basenames (not `.dds`) — DDS→PNG conversion happens in `link_flythrough_textures.py`
- `resolve_texture_urls()` looks up by full `.png` basename; the `.removesuffix(".dds")` is a no-op safety net for future data shape changes
- If basenames change to `.dds` in the future, `index_converted_textures()` would need to also index by stem (without extension)

### Guard Version Management

- `scene_manifest_validation_guard` uses exact string matching for producer version
- Any future `PRODUCER_VERSION` bump in `build_scene_manifest.py` must also update the guard
- This tight coupling is by design — guards are meant to fail loudly on unexpected changes

### Path Privacy

- Emitted JSON must never contain absolute Windows paths — `_assert_no_absolute_paths()` is a hard guard
- Input paths use `CYCLE2_ROOT = REPO_ROOT / "Assets" / "Exports" / ...` (keeps the canonical nested data tree)
- Output paths use relative references only (`obj_mesh`, `asset_id`)
