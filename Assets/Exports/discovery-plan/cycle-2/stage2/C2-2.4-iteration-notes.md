## Schema gaps (for V4P12 review)

1. **`Geometry` is too permissive for a consumer-ready manifest.** A
   `consumer_ready: true` manifest should require `vertex_count > 0` AND
   `face_count > 0` (or, for point-only assets, `has_faces: false` with
   `vertex_count > 0`). Today's schema would accept a zero-vertex "consumer
   ready" manifest, which would silently break a renderer.
2. **`Materials.material_status="unknown"` + `texture_property_count=0` is
   a valid combination for a textured asset that hasn't been re-scanned.**
   The schema can't distinguish "scanned, found zero" from "never scanned".
   A `scanned_at` timestamp on `Materials` would close this gap.
3. **No `geometry.obj_sha1` field.** A consumer that wants to detect OBJ
   re-exports needs a content hash. The `asset-mesh-manifest-v1` schema
   already has this field; `scene-manifest/v1` should mirror it for
   cross-schema consistency.
4. **No `world.accumulated_transform` vs `world.declared_transform`
   distinction.** The current `world_transform_summary` collapses both
   interpretations. The semantics.md decision (mesh-node parent-chain
   accumulation) is the accumulated value, but a consumer might want
   to compare against the declared node transform for debugging.

These are open questions for V4P12, not blockers for C2-2.4 acceptance
(schema validates as JSON Schema 2020-12 — done).
